# 回声记忆 / Echo Memory

[English](README.md) · [Agent 上下文](docs/agent-context.md) · [MCP 说明](docs/mcp.md) · [安全说明](SECURITY.md)

**回声记忆是一款面向 macOS 的本地优先谈话记忆库。** 它将重要音频变成可搜索的逐字稿、可追溯的决策与待办，以及能够再次提供给 AI 工具使用的项目上下文。

它不是一次性的会议纪要工具。它要解决的是：你能否回到**当时说了什么、为什么这么决定，以及这个结论的出处在哪里**。

> 当前状态：Alpha。现阶段提供源码构建方式，尚未发布签名的 macOS 安装包。

## 为什么做它

大量项目背景都发生在电话、访谈、客户沟通、复盘和个人口述里。录音很难重听，摘要可能丢失依据，而 Codex、Claude、Cursor 等 AI 工具又常常缺少过去决策的上下文。

回声记忆将音频、带时间点的逐字稿、结构化分析和原文出处留在同一台 Mac 上。每个重要结论都应能回到原话和对应音频位置，而不是只留下一个无法核对的总结。

## 当前能力

- 导入 `MP3`、`M4A`、`WAV`，保存到受管理的本地资料库，并以哈希检测重复文件。
- 使用内嵌 Whisper 或本机 `whisper.cpp` 命令进行本地转写；点击片段即可跳转播放，修订逐字稿时不覆盖原始文本。
- 使用本机 Ollama 模型整理摘要、关键观点、决策、待办和未解决问题。
- 决策与待办关联原文逐字稿片段；出处无法验证时明确标记，而不是编造引用。
- 按项目形成个人知识库，搜索标题、逐字稿、摘要、决策和待办，并显示时间范围。
- 用户主动开启后提供本机只读 MCP，让 AI 工具查找带原文依据的历史上下文。

## 本地优先，不是一句口号

音频、逐字稿、SQLite 数据库与 MCP 都在本机运行。当前 Alpha 不上传音频或逐字稿，不会静默切换到云端处理，不开放公网端口，也不允许 MCP 写入资料库。

相应地，本地转写和分析需要本地依赖。模型缺失或分析失败会明确显示，且绝不会损坏已保存的音频和逐字稿。

## 工作闭环

```text
导入音频
  -> 本地生成带时间范围的逐字稿
  -> 提取带出处的决策与待办
  -> 归档到项目知识库并全文搜索
  -> 通过只读 MCP 让 AI 查询相关历史
```

## MCP：让 AI 有出处地找回历史

MCP 默认关闭。用户在应用中主动开启后，回声记忆提供一个本机 stdio、只读的 MCP Server，可搜索记录、读取有限范围的逐字稿、列出项目、获取项目上下文和待办。

它只记录调用元数据，不记录音频、逐字稿正文或密钥；不监听公网端口，也不能写入、编辑或删除资料。请阅读 [MCP 说明](docs/mcp.md) 查看工具清单与开发配置。

## 个人知识库与第二大脑

每次谈话可以归入一个项目。随着资料积累，反复出现的决定、承诺、问题和原话会跨记录变得可查。回声记忆不试图取代你的笔记，而是保留一层可验证的工作记忆，供你和 AI 在需要时找回与核对。

## AI 硬件与录音卡

当前回声记忆接收导出的音频文件。只要 AI 录音设备、录音卡、手机或录音笔可以导出 MP3、M4A 或 WAV，文件就能进入同一套本地流程。当前 Alpha 不提供任何特定硬件的直连或官方兼容承诺。

## 环境要求

- macOS
- Node.js 18+、Rust stable、Cargo、Xcode Command Line Tools；首次构建内嵌 Whisper 时需要 CMake
- 本机可读的 Whisper `ggml-*.bin` 模型
- 可选：本机 `whisper-cli` / `WHISPER_CPP_BIN`
- 可选：本机运行的 Ollama 服务与模型，用于分析

## 本地运行

```bash
cd app
npm install
bash scripts/check-env.sh
npm run tauri dev
```

默认资料库位置为 `~/Library/Application Support/回声记忆`。开发和测试时可设置 `ECHO_LIBRARY_ROOT` 使用独立目录。

## 验证命令

```bash
cd app
npm run typecheck
npm run build
cd src-tauri
cargo fmt --check
cargo test --features mcp-bin
```

## 范围与路线图

Alpha 聚焦单用户、单设备、本地闭环。目前不提供实时录音、自动入会、手机端、Windows、云同步、团队协作、支付/额度、公开 API、外部系统写入或 MCP 写入。

未来可能探索更高质量处理和音频硬件工作流，但这些都不是当前功能承诺。
