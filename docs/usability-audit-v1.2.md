## 场景走查结论与 Findings

### S1 首次启动（向导 → 第一支录音）

结论：五步全可跳过；不配模型也能先录（录音不检查模型，入库状态「等待转写」，转写失败进详情页可重试）。体验主干成立。

- **F5 [P1] 「重新运行引导向导」承诺自动弹出但实际要重启**。
  证据：SettingsPanel.tsx:780-781 文案「重新走一遍模型与收件箱配置流程。关闭设置后会自动弹出。」；App.tsx:53-66 只在挂载时查询一次 onboarding 状态，关闭设置不触发。复现：设置 → 关于 → 重新运行引导向导 → 关闭设置 → 无弹窗（UI 层未验证，代码层实锤）。
  为什么不合理：文案承诺的行为没实现，用户等一个不会出现的弹窗。
  建议改法：resetOnboarding 成功后立即置 onboardingNeeded=true（前端一行）。

### S2 麦克风录音生命周期

结论：录→暂停/继续→停止入库→放弃（有确认）→崩溃恢复，全链路状态可见、可逆；停止失败有恢复入口与防幽灵态（pollGeneration，RecordingEntry.tsx:153-156）。

- **P2-1** 列表里失败转写只显示「转写失败」三个字，原因与重试都在详情页（RecordDetail.tsx:726「重新转写」）——列表层没有原因与重试入口。
- **P2-14** 暂停期间电平条停留在最后一帧数值（system_audio.rs:398-416 保留 levels），可能被误读为还在收音。

### S3 系统声录音

结论：三重门完整（macOS 屏幕与系统声音权限 → 应用内 SYSTEM_CAPTURE_NOTICE 告知确认 → 后端 confirmed 硬门 system_audio.rs:1104-1106）；权限被拒文案指路明确且明示「麦克风录音不受影响」；**没有静默改走麦克风的路径**（前端注释与抛错路径双重保证，RecordingEntry.tsx:9-11/:292-294）。

- **P2-2** 系统声流被系统中断时文案说「本次不保存」（system_audio.rs:728-737），但会话标 `failed` 而 `failed` 会进恢复列表且可恢复（recording.rs:661）——文案比实际悲观，属「误导但方向安全」。
- **P2-15** 恢复列表里才出现「系统声音 ·」来源前缀；正常记录列表无来源标记，只能靠标题里「系统录音/本地录音/双路录音」字样区分（RecordPanel.tsx:74-75 只区分 document/chat）。

### S4 双路录音

结论：来源三选文案与 DUAL_CAPTURE_NOTICE 清楚讲明「合并成一个立体声文件（左=麦克风，右=系统声）」；停止后确实入库 **1 条**合并记录（dual_recording.rs stop_inner，副会话以 canceled+record_id 记账并入）；失败绝不静默降级为单路（整单回滚，dual_recording.rs:214-233）。承诺与行为一致。

- **P2-3** 停止中途失败时，一次「停止并保存」可能换来恢复列表两行未知音频（麦克风+系统声各一行），行间无「同属一次双路」的关联提示。
- **P2-16** 双路转写在转写层把立体声混回单声道，左右声道分离在逐字稿里丢失——此已知限制只写在代码注释（dual_recording.rs:8-10），界面文案未告知。

### S5 实时文字 + 实时增量纪要

结论：实时文字口径成立（「边录边出，停止后以全量转写为准」，暂定行用浅色 + … 后缀）；实时纪要标题自带「暂定，以事后为准」；停止后实时区整体收起、权威=事后纪要，无冲突残留。

- **F4 [P1] 实时纪要在 Ollama 不可用时静默退化**：模型不可用直接 return（live_minutes.rs:199-202 注释自认「已知静默退化，不另发事件」），实时纪要区永不出现、无一句解释。用户无法区分「还在听」与「这个功能没在工作」。
  复现：无 Ollama 环境录音 → 实时文字正常、实时纪要区不出现且无提示（代码层实锤；UI 层未验证）。
  为什么不合理：状态看不见；同一界面另一半（实时文字）的同类失败有明确提示文案，行为不一致。
  建议改法：模型检测失败时发一次性状态事件，前端在实时纪要区显示一行说明（如「实时纪要需要本机 Ollama，未检测到；录音与实时文字不受影响」），不改变任何数据行为。
- **P2-4** 实时纪要事件带出的 dropped_unverifiable 前端未展示（live_minutes.rs:47-49 有数据，RecordingEntry 只渲染三类数组）。

### S6 事后纪要

结论：议题/结论/待办/术语表齐全；dropped 计数透明（「宁缺毋假」文案）；失败可无限重试（生成闩 600s 防并发）；生成是后台线程不阻塞其他操作。**「每条可点回原文」部分成立**：时间戳是按钮、点了 seek 音频并自动播放（RecordDetail.tsx:467-485），引文 blockquote 常驻展示；但点击不切逐字稿 tab、不高亮对应句——与内容分析 tab 的 onSeek 行为不一致（AnalysisView 会 setActiveTab("transcript")+高亮+scrollIntoView，RecordDetail.tsx:793-801）。

- **P2-5** 纪要证据回链不切换/不高亮逐字稿（同上），与内容分析的证据跳转行为不一致。
- **P2-5b** 纪要生成中无进度/预计耗时提示（每 2s 轮询但只显示「正在生成本机纪要…」）。

### S7 确认入记忆（含 MCP 黑盒探针）

结论：两态徽标（「暂定」/「已确认」）与按钮（「确认入记忆」/「撤回」）双向随时可逆；生成窗口期禁用确认（防注定丢失的操作）；重新生成后全部回到暂定（隐私红线，注释明示）；确认后 UI 溯源信息不减少。

### S8 文档导入 + AI 对话导入（定位命门）

**盘点结论**：两条导入路径都存在且完整（非半成品）。文档导入支持 md/txt/docx（本地解析+分析管线）；AI 对话导入支持 ChatGPT/Claude JSON、对话式 md/txt、Agent 会话扫描（Claude Code/Codex 白名单位置）。入口在「工作区」三个分组组头（录音/文档/AI 对话），组头即导入入口。

**三路规则对照**（vs 录音路）：

| 维度 | 录音 | 文档 | AI 对话 |
|---|---|---|---|
| 暂定→确认两态 | 有（minutes_items） | **无，导入即落库** | **无，导入即落库** |
| 溯源坐标 | 真实音频时间+引文 | 伪时间轴（800 字块=1s）+段定位 | 伪时间轴+用户/助手标签 |
| 逐条分析 | 跑 | 跑（会进记忆链） | **不跑**（只建索引） |
| 记忆链 | 有 | 有 | 无（结构化产出=梳理报告） |
| 知识索引/搜索 | 有 | 有 | 有 |
| MCP 原文读取 | 可读（by design） | **可读，无门槛** | **可读，无门槛** |
| MCP 记忆层 | 仅 confirmed 条目 | 不产生条目 | 不产生条目 |
| 待处理队列 | 是 | 是 | 否（「对话档案」语义） |

- **F1 [P1] MCP 口径文案缺口（块3 已实锤候选，探针+代码双证实）**：全应用没有任何地方讲明「确认门槛只保护纪要条目层，逐字稿/文档/AI 对话原文对 MCP get_record/get_transcript 本来就可读（v1.0 by design）」。现有文案（「只读」「确认后才可被 MCP 读取」）会让用户合理推断「MCP 只能看到我确认过的内容」。
  证据：mcp.rs:58 `authorized_scope: "全部知识库（只读）"`；ProjectPanel.tsx:206 只显示这一句；探针实测 get_record(B归档)/get_record(C chat) 原文可读。
  建议改法：把 authorized_scope 文案扩为一句如实说明（如「全部记录的标题、逐字稿与文档原文（只读）；记忆条目仅限已确认内容」），MinutesPanel 确认按钮 title 补「（记录原文不受此门槛限制）」。
- **F2 [P1] chat 导入文案与行为不符**：按钮「导入并分析（N 个文件）」、成功提示「AI 对话已导入，分析正在后台进行」、步骤 3「后台分析……可在认知演化中确认」（ChatImportDialog.tsx:434-435/:511，RecordPanel.tsx:851）——但 chat 实际**不做逐条分析**（commands.rs:1198-1216 注释明示独立车道）、也没有可确认的条目。
  为什么不合理：文案说了没做的。复现：导入一个对话式 md → 成功提示说在分析 → 认知演化里永远没有该对话的条目。
  建议改法：文案改为与「对话档案」定位一致（「导入后立即可搜索、可被问答引用；梳理报告把它们归纳成正在推进的事」），去掉「分析/确认」字样。
- **F3 [P1] Agent 会话扫描默认全选**：扫描结果默认勾选全部会话（ChatImportDialog.tsx:118-124），「导入前可见、可取消」的实际颗粒度是文件级（标题=首条用户消息前 60 字，agent_scan.rs:269-273）。用户一路「导入所选」会把全部会话（可能含代码、密钥等敏感内容）入库，且原文对 MCP 可读。
  复现：有 10 个 Claude Code 会话 → 扫描 → 全部默认勾选 → 一键导入。
  为什么不合理：批量外发式默认 + 内容不可见，与「经用户确认、可溯源」的定位有张力。
  建议改法：默认不勾选（显式选择才导入），组级勾选框保留批量能力；不改数据结构。

- **P2-7** 导入入口只在 RecordPanel 分组组头；知识库首页与工具栏没有导入入口，首次可发现性一般。
- **P2-8** Agent 会话导入无内容级预览（只有标题/日期/大小）。
- **P2-9** document/chat 记录的伪时间轴（每 800 字块=1 秒）出现在搜索结果时间坐标、SRT 导出、问答引用中（document.rs:398-399、chat_import.rs:626-629），对非录音记录有误导性；SRT 对这两类记录无字幕意义，代码未拦截。
