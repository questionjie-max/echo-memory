## ✅ P0 · 「长录音转写幻觉回归」——已解除（2026-09-21，根因是基准 harness 缺陷）

**原判（2026-09-19，错误）**：凯旋北路（37min 电话录音）用当前流水线重跑产出英文幻觉循环，
判定为「增强管线回归」，并警告用户勿对长录音点重新转写。

**真实根因**：基准跑器（transcription_benchmark_test）的「真实录音」分支**忘记设置转写语言**，
沿用了跑完五条片段后的设置——最后一条是英文片段，语言停在 `en`。37 分钟的中文录音被
**强制按英语转写**，whisper 对错语言输入的典型反应正是英文循环/外语标注。
代码走查中也确认：库里 69 条转写有 **68 条是增强管线（enhanced-v2）产出**，从 07-19
一路用到今天；唯一那条好转写（legacy-v1）恰好是从未被增强管线处理过的一条。

**证伪与证实链**（全部在 benchmarks/results/ 留档）：
1. 消融 A：关掉 ffmpeg 滤波（afconvert 路径）→ 仍幻觉 → 排除预处理（当时未意识到语言是 en）
2. 消融 B：整文件单次解码 + 显式 `zh` → 1310 段通顺中文，99% 中文占比（tests/long_recording_ablation_test.rs）
3. 块级消融：48 个块逐个用 `zh` 解码 → 全部健康（tests/chunk_level_ablation_test.rs）
4. **修正 harness 语言后重跑真实管线** → 362 段通顺中文，开头与库内 legacy 好转写一致
   （results/20260921T121656Z-*.json）

**沉淀**：
- 基准 harness 的语言泄漏已修复（真实录音分支显式设语言，默认 zh，可用 ECHO_BENCH_REAL_LANG 覆盖）
- 两个消融测试固化为 ignored 测试，作为未来转写归因的基础设施
- 2026-09-21 落地的**退化检测闸门**（见下）恰好能拦住这类「语言不符」输出——
  如果它当时在位，这次误判在跑分阶段就会被标记而不是被写成结论

**仍存疑的一条（不阻塞）**：库内「蒋艺峰声纹」（86s，08-22，ggml-small，enhanced-v2）
的输出是中文乱码（「但是西偏套有需要无所谓」），19 分钟后静默停止。该录音被手机消息
提示音等噪音环绕，疑为借用的小模型在真实噪声下的退化；当前管线未复现同类问题，
且退化闸门现在会拦截。记 L12。

**状态**：已知 P0 产品故障已解除；真实长录音回归已完成并归档。正确语言设置下的真实
长录音复跑通过退化检测、时间轴检查和人工内容核对，68 条在库产出继续提供旁证。

## ✅ 本期已验证为健康的部分

- 模型下载链路：断点续传、SHA-256 校验、下载后登记、预存在文件短路、损坏清理——
  代码与测试齐备；本次 574MB 实际下载 + 校验一次通过
- 干净音频质量：合成基准 1–6% CER（large-v3-turbo），快于实时（0.22×）
- 抗噪：粉噪声 18% 混入下 CER 5.6%，不劣于干净版
- 热词库价值获数据支撑：基准错误几乎全是专有名词/人名类

  - 摘要准确无幻觉；要点与三个议题一一对应；**引用全部有效**（每条 2–3 个片段，经
    `verify_citations` 校验）；耗时 75s/83s 素材
  - 「截止日期十月一日」这类提醒**没有**被误判成待办（0011 规则生效）
  - 忠实传播 ASR 错误（王芳→王方），行为符合预期
  - 归类边界问题见 L6；明细 results/20260919T154047Z-analysis-qwen2.5:7b.json

| 它的做法 | 对我们的启发 | 建议优先级 |
|---|---|---|
