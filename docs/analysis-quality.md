# 分析质量评测：结构闸门 + 人工矩阵（v0.9）

> 目的：给「转写后的分析」补上质量验收标准。转写侧早有退化闸门（`src/degeneration.rs`），
> 分析侧此前只有零散单测——本文件补齐两道门，作为 prompt 迭代与发布前的验收依据。
> 结构参考了得到大脑逆向报告（2026-10-14）的验证方案，但断言、模板与判定标准均按本项目
> 的证据链体系重写，不引入对方提示词文案。

## 1. 两道门

| 门 | 载体 | 何时跑 | 管什么 |
|---|---|---|---|
| A. 自动化结构闸门 | `app/src-tauri/tests/analysis_quality_e2e_test.rs`（`--ignored`） | 改分析 prompt / 校验 / 模板后，发布前 | 只断言不变量：结构完整、引用可验证、章节时间序、指令被遵守、无材料时不编造 |
| B. 人工质量矩阵 | 本文件 §3 | 需要判断「写得好不好」时 | 结构遵从 / 指令遵从 / 事实忠实 / 不确定性表达 / 语言策略 五维打分 |

自动化门不评价文风与信息密度（模型输出天然有波动，自动打分不可靠）；人工矩阵不追求每次都跑，
但它给出「这次改动到底让输出变好还是变差」的统一标尺。

## 2. 运行自动化闸门

```bash
cd app/src-tauri
ECHO_E2E=1 ECHO_ANALYSIS_MODEL=qwen2.5:7b cargo test --features mcp-bin \
  --test analysis_quality_e2e_test -- --ignored --nocapture
```

覆盖三个场景（对应得到大脑报告里的 T5/T6/T9，改写为本项目形态）：

1. **长文默认分析**：>4500 字走分块合并路径；断言摘要非空、关键观点 ≥3 条且全部带可验证引用、
   章节时间严格递增（有则必查）、金句引用完整、无 Blocking。
2. **带补充信息的短会**：指令「只保留待办事项，按负责人分组」；断言待办有引用，而关键观点 /
   决策栏目为空——即补充要求真的覆盖了默认结构（T6 的核心）。栏目取舍由
   `apply_instruction_section_filter` 确定性执行，模型"愿不愿意"不再影响结果。
3. **材料不足的闲聊**：无决策、无待办、无未决问题的素材；断言三个栏目都为空数组而不是编造，
   摘要用于显式说明材料情况（人工复核措辞，见 §3 第 4 维）。

失败时的判断顺序：先看是不是模型能力问题（换 `ECHO_ANALYSIS_MODEL=qwen3.5:4b` 重跑对比），
再看是不是 prompt 回归（对照 `src/analysis.rs` 的提示词规则行）。素材本身没有可摘录原话时
（例如高度重复的合成逐字稿），金句为空是正常结果，属人工矩阵 T7 的素材问题而非缺陷。

2026-10-14 首跑基线（qwen2.5:7b）：三场景全过；长文场景产出 6 章节、0 金句（合成素材无金句感），
闲聊场景三栏目全空且摘要主动说明"未涉及明确决策或行动项"。

## 3. 人工质量矩阵

素材取本地真实录音（建议：一条 20 分钟以上会议、一条 3 分钟速记、一条带明确待办的讨论），
每种组合跑 2–3 次观察稳定性；用「分析模板」下拉与「补充要求」输入框控制变量。

| # | 素材 | 模板 | 补充要求 | 判定重点 |
|---|---|---|---|---|
| T1 | 标准会议逐字稿 | 标准会议 | 无 | 摘要具体、观点/决策/待办各归其位，不互相复制 |
| T2 | 客户访谈 | 客户访谈 | 无 | 「核心需求 / 痛点」栏目有原话证据，不把客套话写成需求 |
| T3 | 项目复盘 | 项目复盘 | 无 | 事实与原因判断分开，猜测不进结论 |
| T4 | 同 T1 素材 | 标准会议 | 「只保留待办事项，按负责人分组」 | 未要求栏目为空；待办可按人分组；引用仍逐字 |
| T5 | 20 分钟以上会议 | 标准会议 | 无 | 章节 2–6 个、时间递增、summary 一句话可用；点击可跳播 |
| T6 | 同 T5 素材 | 标准会议 | 「章节标题控制在 8 字内」 | 章节标题变短（指令对新增栏目同样生效） |
| T7 | 含金句的访谈 | 客户访谈 | 无 | 金句是原话（可与逐字稿逐字比对），不是改写或总结 |
| T8 | 录音质量差 / 极短素材 | 任意 | 无 | 该空的栏目为空，摘要显式说明材料不足 |
| T9 | 同 T1 素材重复 3 次 | 标准会议 | 无 | 结构稳定性；标签/章节数量漂移在可接受范围 |

### 五维打分（0–2 分/维）

- **结构遵从**：固定栏目齐全、顺序正确；模板自定义栏目按 key 与顺序返回。
- **指令遵从**：补充要求被最高优先级执行；出现用户未要求的内容直接 0 分。
- **事实忠实**：与逐字稿对照，编造一次扣 1 分；引用是否逐字可点开复核。
- **不确定性表达**：材料含糊/缺失处有显式说明，不硬凑、不推测补齐。
- **语言策略**：简体中文；专有名词保留原文时首次出现给解释；不中英混杂输出。

### 判定标准

- 单次运行总分 ≥8/10 视为通过；同一素材 3 次运行里出现 1 次 ≤6/10，按 prompt 回归处理。
- 「事实忠实」或「指令遵从」任一次得 0 分：即使总分够，也判不通过——这两维是证据链底线。

## 4. 与代码的对应关系

| 质量点 | 落点 |
|---|---|
| 统一收口顺序（别名解析 → 指令裁剪 → 引用校验） | `src/analysis.rs::finalize_analysis_draft`；分析、重新校验、E2E 三处共用 |
| 引用逐字校验（fail-closed） | `src/analysis.rs::verify_citations_inner`；失败条目整条丢弃 |
| 章节时间序 / 金句逐字闸门 | 同上（chapters / highlights 分支） |
| 补充要求优先级与不可覆盖项 | `instruction_block()` 与单段/纠错/合并三处注入 |
| 「只保留 X」的确定性栏目裁剪 | `apply_instruction_section_filter`：排他措辞 + 点名栏目才触发；识别不出点名栏目不动结构 |
| 有指令时放宽栏目下限 | `analysis_quality_assessment_for_instruction` |
| 不确定性表达规则 | 单段分析提示词的「不确定性规则」行 + 合并提示词同义句；材料完整时禁止杜撰缺口说明 |
| 空栏目不编造 | 提示词「没有证据就返回空数组」+ 质量闸门 + 人工矩阵 T8 |
