# ADR：v1.0 本地录音采集后端

- 状态：已接受，作为采集 spike 的决策基线
- 日期：2026-10-16
- 范围：macOS 单用户、单设备、本地麦克风录音

## 背景

回声记忆 v0.9 已经具备音频文件导入、转写、分析、证据校验、检索和记忆召回，但没有应用内麦克风采集。v1.0 需要新增采集层，同时保持本地优先、原始音频可回放、第三方上传需要独立同意，并复用现有 `ManagedLibrary::import_audio` 管线。

当前仓库已有 `symphonia`/`hound` 用于导入、时长探测和预处理后的 WAV 读取，但没有音频设备采集依赖，也没有 AVFoundation/AudioUnit/cpal/WebView MediaRecorder 实现。应用是 macOS-only 的 Tauri 2 桌面应用，正式发布包含 Developer ID 签名、公证和 bundle audit。

## 决策

### 1. 采集后端优先使用 AVFoundation 高层接口

第一选择是 macOS 原生 AVFoundation 的高层录音能力（`AVAudioEngine` + `AVAudioFile`，或经 spike 证明更稳的 `AVAudioRecorder`）。原生层只负责：

- 请求/检查麦克风权限；
- 枚举或读取当前输入设备；
- 将输入流持续写入资料库外的临时 WAV；
- 暂停、继续、停止、取消和输入电平；
- 把设备错误/音频中断传回 Rust 控制器。

Rust/Tauri 层负责录音会话状态、checkpoint、临时文件封存、恢复和交给 `ManagedLibrary::import_audio`。采集回调不做转写、网络请求或重型重采样。

### 2. 输出优先为 PCM WAV

WAV 是当前导入白名单支持的格式，停止后能被 Symphonia、现有播放器和预处理链读取。设备原生采样率与声道先保持稳定，既有预处理负责转为 16kHz 单声道用于转写。不要为了“实时”在采集回调中运行 AI。

### 3. 保留可替换的 `RecordingBackend` 抽象

上层只依赖以下语义：

```text
start(config)
current_level()
pause()
resume()
stop()
cancel()
```

AVFoundation 是首个实现；如果签名 release 无法稳定桥接，或以后需要跨平台，再在同一抽象下评估 Rust `cpal`。抽象不是为 v1.0 引入多后端，而是防止设备生命周期和 UI/资料库耦合。

### 4. 不采用 WebView `MediaRecorder` 作为正式实现

原因：

- WebKit 的 MIME/编码可能输出当前白名单没有的 WebM/Opus；
- 长录音依赖 JS Blob/IPC 写盘，不适合本项目的长音频与恢复要求；
- 权限来源和打包应用行为需要额外验证，不能替代原生 TCC 处理；
- 页面刷新、窗口关闭或 WebView 崩溃会增加未封口数据丢失面。

短时原型可以用来验证交互，但不得作为 v1.0 的数据可靠性基础。

### 5. 不直接使用裸 AudioUnit

AudioUnit 留给未来的低延迟、系统音频或复杂设备路由需求。v1.0 只录麦克风，使用 AVFoundation 高层 API 可以减少格式、render callback、buffer 生命周期和中断恢复的自定义代码。

## 约束与验收

- 正式 `.app` 必须包含非空 `NSMicrophoneUsageDescription`；bundle audit 应从“人工查看”升级为确定性检查。
- 不为录音增加全盘访问或其他无关 entitlement；如果未来启用 App Sandbox，才按实际需要评估 audio-input entitlement。
- 录音默认不发网络请求；停止后若用户选择外部 ASR，仍走既有独立音频上传同意和 URL/host 安全校验。
- 采集临时文件不能进入 `audio/` 或转写队列，直到 flush/close、hash、时长和正式记录事务成功。
- 开发构建和签名 release 构建都必须在真机验证权限和 WAV 可读性；只在 `tauri dev` 通过不算通过。
- 采集 spike 失败时，不得悄悄改成 WebView MediaRecorder；应在 `cpal` 与原生桥接之间做有记录的重新决策。

## 后续拆分

1. Spike：证明权限、10 秒 WAV、pause/resume/stop、输入电平、内存稳定和无网络。
2. 生命周期：`recording_sessions`、临时目录、checkpoint、封存、恢复。
3. 管线接入：`source_type=recording`，复用 `ManagedLibrary::import_audio`。
4. UI：空闲/录音/停止后/恢复与失败状态。
5. 真机与签名 DMG：权限拒绝/恢复、外置设备、长录音、异常退出、转写回放和发布审计。
