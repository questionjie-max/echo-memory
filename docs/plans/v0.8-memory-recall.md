## 0. 产品方向与技术路线

**产品定位一句话**：回声记忆 = 个人上下文沉淀库。三个入口（录音的听/说、文件资料、AI 对话）→ 一套带证据的沉淀（版本化快照 + 用户确认 + 观点演化）→ 两种召回（问知识库问答、MCP 供外部 Agent）。v0.8 要修的断点：**沉淀了但召回不了**——确认过的记忆查不到、打字侧的内容（AI 对话）进不来、记忆缺最顶层的总述。

**技术路线五条约束**（所有实现必须在此框架内）：
1. 不引入新框架、新数据库、新服务——全部在 Tauri 2 + Rust + SQLite + Ollama 现有架构内扩展；
2. 零新依赖——JSON 解析用现有 serde_json，Markdown 对话解析手写行级状态机；
3. 复用现有管线——chunk→embed→RRF→引用 fail-closed 校验这条链不动，只增加「记忆」这一来源；
4. 安全边界不放松——外部文件内容一律当数据不当指令（沿用 `<UNTRUSTED_*>` 边界），MCP 保持只读，不新增任何数据外发路径；
5. 本地优先不变——新功能全部本地可跑；外部 AI 仅用于总述生成，沿用现有双同意门禁。

## 2. 工作包 A：Ollama 超时护栏（搭车修复）

**怎么干**：knowledge.rs 的 `embed_texts`（120s）、`ensure_model_installed`（10s）、`generate_answer`（600s），analysis.rs 的 Ollama 调用同样处理。memory.rs 外部 AI 客户端已有 120s 不动。

**验收**：OLLAMA_HOST 指向无响应端口 → 问知识库在超时后报明确错误，UI 不永远转圈。

## 3. 工作包 B：AI 对话导入

- **B1 解析器**：ChatGPT 导出 conversations.json（mapping 消息树按序遍历）；Claude 导出 JSON（chat_messages[{sender,text}] 宽松探测）；对话式 Markdown（行首说话人标记，识别不出则走普通文档路径）。逐会话解析，坏会话进 skipped 明细。
- **B2 落库**：会话 → record（source_kind="chat_import"，会话文本 sha256 去重）；turn → segment（speaker=用户/助手，假时间轴序号×1000）；单文件 200 会话上限。
- **B3 前端**：知识库页「导入 AI 对话」按钮（多选 .json/.md）→ 批量进度 → 成功/跳过明细；新 invoke `import_chat_exports`。

**验收**：真实导出导入正确；重复导入去重；坏文件明确报错；导入内容可搜可问答可进认知演化；界面截图走查。

## 4. 工作包 C：确认过的记忆接入知识库检索（核心）

**关键约束**：`knowledge_chunks.record_id` 非空外键 → 记忆块建独立表。

- **C1 数据层**：新 migration 建 `memory_chunks` 表 + FTS 虚表 `memory_chunks_search`（trigram）；`knowledge_index_state` 增 scope_key='memory'。
- **C2 投影**：只收用户**已确认**的 evolutionItems 与 viewpoint/decision 节点；rejected 绝不入库；内容 hash 未变不重复 embed。
- **C3 索引时机**：快照生成完成、批量确认提交后触发 memory scope 重建；以最新版本快照为准，清理失效 snapshot_id。
- **C4 检索融合**：四路（资料向量/资料 FTS/记忆向量/记忆 FTS）RRF 合并；prompt 上下文分「【资料原文】」「【你的过往记忆】」；记忆引用 kind="memory"，quote 逐字校验 fail-closed；记忆路证据阈值用独立常量。
- **C5 前端**：记忆引用卡（「你的记忆」标签、跳记忆视图、可选回听原声）；首页状态条显示 memory scope。

**验收**：确认后能答「我之前对 X 的看法」且引用逐字；驳回/未确认不出现；编造引用被拒；快照重生成旧块不残留；混合提问两类来源标注清楚；无确认记忆时行为与 v0.7.1 一致。

## 8. 实施中的发现与修复（2026-10-11 真机走查）

1. **迁移级联事故（已修复+已恢复）**：0019 重建 memory_snapshots 时，业务连接的
   `PRAGMA foreign_keys=ON` 会让 DROP TABLE 级联清空 memory_feedback（迁移自测
   连接 FK=OFF 故未捕获）。真实库 7 条确认反馈曾被清空，已从迁移前备份完整恢复
   （备份：`回声记忆-backups/memory.db.pre-v08-20261011-225545`）。修复：迁移中
   显式转移写回反馈 + FK=ON 回归测试。全表对比确认无其他数据损失。
2. **单条确认不触发记忆索引（已修复）**：原挂钩只在批量确认上；单条确认命令
   `update_memory_feedback` 现在同样触发重建。
3. **profile 总述保守性验证**：真实库生成成功，模型对未确认条目保持保守措辞，
   已驳回条目不进总述（代码过滤）。

## 9. 风险与预案

| 风险 | 预案 |
|---|---|
| 记忆块与资料块余弦分布不同，共用阈值误杀 | 阈值拆成独立常量，真机校准 |
| 导出格式跨版本漂移 | 宽松字段探测 + 逐会话跳过 + 明细报错 |
| 用户中途换过 embedding 模型 | content_hash+embedding_model 双校验，不一致不参与检索并提示重建 |
| 确认率低导致记忆路为空 | 状态条显示 memory 条数，引导确认（一键全部确认已有） |
| 大导出文件 | 200 会话上限 + 逐会话进度事件 |
