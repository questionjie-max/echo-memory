# v1.0 本地录音：产品契约与验收矩阵

> 状态：设计基线，尚未宣称 v1.0 发布。
> 分支：`feature/v1.0-local-recording`
> 基线版本：v0.9.0

## 1. 产品承诺

v1.0 的承诺不是“做一个功能更多的会议录音软件”，而是：

> 在单用户、单台 Apple Silicon Mac 上，用户可以显式开始一次本地麦克风录音；停止后，原始音频可靠保存，并自动进入既有的转写、分析、证据化检索和记忆确认流程。

这补上的是“重要上下文进入个人记忆系统”的采集入口。录音本身不是终点：原始音频、逐字稿、分析结论和用户确认过的记忆必须保持可区分、可回溯、可纠正。

## 2. 目标场景与明确边界

### 目标场景

- 个人口述、语音备忘和产品思考；
- 获得必要授权的线下谈话或会议；
- 电脑旁发生、希望立即保留下来的重要上下文。

### 不承诺的场景

v1.0 只录本机麦克风，不捕获系统音频。因此它不承诺完整记录 Zoom、Meet、Teams 等线上会议的远端声音。系统音频捕获、麦克风混音和自动入会必须另立产品与技术课题。

v1.0 不包含：

- 实时逐字转写或实时说话人分离；
- 自动加入会议、会议机器人；
- 云同步、手机端、团队空间；
- 后台隐蔽录音或未经明确操作的持续采集；
- 未经用户确认把一次录音中的推断直接写进长期个人画像。

## 3. 用户流程

```text
开始录音
  -> 麦克风权限与设备检查
  -> 临时录音文件 + 持久化录音会话
  -> 录音中 / 暂停 / 继续
  -> 停止并关闭文件
  -> 校验格式、时长、hash、磁盘
  -> 现有 ManagedLibrary::import_audio(source=recording)
  -> records + transcribe job
  -> 现有转写、分析、引用、检索和记忆确认
```

录音阶段不占用现有重任务并发名额，也不触发第三方服务。录音结束后才进入处理队列；外部 ASR 仍必须通过现有的独立音频上传同意门禁。

## 4. 状态机

录音会话与处理任务是两套状态，不得把“录音中”塞入 `RecordStatus` 或 `processing_jobs`。

```text
idle -> starting -> recording <-> paused
recording/paused -> finalizing -> completed
recording/paused -> canceled
starting/recording/paused/finalizing -> failed
应用异常退出 -> recoverable
recoverable -> finalizing（用户恢复）
recoverable -> discarded（用户明确放弃）
```

现有处理状态 `queued / preparing / transcribing / analyzing / completed / failed` 只描述录音已经封存后的工作。

### 状态不变量

- `recording` 和 `paused` 必须有一个仍可写入的临时文件；
- `finalizing` 不再接受音频写入，必须先完成 close/flush；
- 只有文件校验、hash、时长和正式记录创建成功后，才进入 `completed`；
- 任何失败都保留错误和临时文件，不能静默删除；
- `canceled` 不创建正式录音记录，但只有在确认文件不再需要后才清理；
- `recoverable` 不会自动进入转写，必须由用户恢复或明确放弃。

## 5. 数据与文件边界

新增独立的 `recording_sessions` 表，采用新增迁移，不重建已有父表。至少记录：

- session id 与状态；
- 资料库内相对临时路径；
- 开始、结束、最后 checkpoint 时间；
- 有效录音时长和暂停累计时长；
- 输入设备标识/名称、采样率、声道、写入字节数；
- 最终 `record_id`；
- 最近错误和更新时间。

临时文件放在：

```text
<library-root>/recordings/inflight/<session-id>/capture.wav
```

临时文件不进入正式 `audio/`，不进入转写队列，也不通过 asset protocol 暴露给播放器。停止时先 flush/close，再由现有 `ManagedLibrary::import_audio` 计算 hash、探测时长、复制进正式资料库并创建记录和任务。只有整条导入事务成功后才能删除临时文件。

正式记录需要区分 `source_type=recording` 与外部导入的 `source_type=import`。

## 6. 采集技术边界

### 首选

macOS 原生 AVFoundation 高层接口（`AVAudioEngine`/`AVAudioFile` 或等价的 `AVAudioRecorder`），通过薄桥接接入当前 `.app`。录音输出优先为当前导入管线稳定支持的 PCM WAV；设备原生采样率、声道和 16kHz 单声道预处理由既有后处理链负责。

### 备用

在相同的后端抽象下评估 Rust `cpal`，仅当原生桥接无法稳定进入开发包和签名 release 包，或未来明确需要跨平台时采用。

### 排除

不把 WebView `MediaRecorder` 作为正式实现。其 MIME/编码可能产生当前白名单不支持的 WebM/Opus，且长录音和异常退出会把可靠性绑定到 JS Blob/WebView 生命周期。

## 7. UI 契约

### 空闲

录音组入口显示清晰的“开始录音”，与“选择音频”分开；说明默认保存在本机，首次使用会请求麦克风权限。

### 录音中

独立的 `RecordingPanel`/sheet 显示：

- 明确的录音红点和文字；
- 已录时长；
- 低频率输入电平；
- 当前输入设备；
- 暂停/继续、停止、取消；
- 不伪装成转写已经开始。

### 停止后

先反馈“已保存，正在进入待处理”，立即把正式记录放入录音组；转写和分析继续在后台执行，模型不可用不能阻塞原始音频保存。

错误必须说明录音是否已经保存，以及下一步是恢复、重试、打开系统设置还是更换设备。

## 8. 验收闸门

| 闸门 | 必须证明 | 证据 |
| --- | --- | --- |
| G0 产品 | 录音降低重要上下文进入记忆系统的摩擦，不是孤立文件夹 | 本文与定位文案 |
| G1 采集 | 权限、开始、暂停、继续、停止和输入电平有效 | 技术 spike 记录、真机走查 |
| G2 数据安全 | 无静默丢失；异常退出可恢复或明确报告 | 状态机/恢复测试、人工演练 |
| G3 格式 | 输出可被现有播放器、Symphonia、预处理和转写读取 | 10 秒与长录音样本、导入测试 |
| G4 管线 | 停止后自动进入转写、分析、引用和检索 | E2E 样本、跳播证据 |
| G5 隐私 | 默认本地；无未经同意上传；权限声明正确 | 包审计、同意门禁测试 |
| G6 发布 | 签名 DMG 与开发环境行为一致 | 签名、公证、Gatekeeper、干净 Mac 记录 |
| G7 价值 | 录音数日后能被找回并帮助完成任务 | 至少 20 次 dogfood 记录与回访 |

以下任一项出现，不进入 v1.0：

- 停止后文件静默丢失；
- 只有开发包能录，签名包不能录；
- 产生无法解释的损坏音频或半成品；
- 录音来源仍被伪装成普通导入；
- 未经同意把音频送到第三方；
- 文案让用户误以为支持线上会议系统音频；
- 未确认推断直接污染个人总述或长期记忆。

## 9. Dogfood 指标

工程闸门通过后，先在本机做至少 20 次真实录音，覆盖个人口述、线下谈话、外接麦克风、暂停/继续和异常退出。每次记录：

1. 是否成功开始；
2. 是否成功保存；
3. 转写/分析是否完成；
4. 数日后是否能通过搜索或 AI 问答找回；
5. 找回的证据是否帮助了一个决定或行动。

不以按钮数量作为 v1.0 成功标准。最重要的硬指标是 0 次静默丢失，以及出现多次“录音后再次召回并实际使用”的案例。
