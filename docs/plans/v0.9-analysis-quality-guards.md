# v0.9「分析输出质量 + 工程护栏」实施方案

> 状态：实施完成，待验收后合并（分支 `feature/v0.9-analysis-guards`，自 v0.8 尖端切出）。
> 范围来源：2026-10-14 得到的《得到大脑逆向分析报告》对照结论，用户选定两组：
> **A 分析输出质量**、**B 工程护栏**。采集侧（录音/快记热键/系统内录）与情报归档不在本次。

## 0. 从逆向报告里取什么、不取什么

取：可落地的**行为级做法**与**验收标尺**——非激活面板式速记窗设计（留给采集侧）、录音生命周期
边界语义、磁盘/保留参数、模板 × 自定义指令的输入契约、输出结构（章节/金句/标签）、
防幻觉与不确定性表达、验证矩阵、以及对方翻车面（开发残留、明文上报、开发域白名单）。

不取：提示词复刻草案的文案（行为反推稿，只当评测基准）；云 ASR 通道（本地 whisper 是差异化）；
私有 TCC 框架与双渲染架构（与我们 Tauri 架构不匹配）。

## 1. 技术路线约束（沿用 v0.8 五条）

不引入新框架/新服务；依赖只新增 `libc`（statfs，本就在依赖闭包里）；复用现有管线与证据链；
安全边界不放松（外部内容一律当数据不当指令，MCP 保持只读）；本地优先不变。

## 2. A 组：分析输出质量

### A1 单条记录「补充信息」指令（迁移 0020）

- `analyses.analysis_instruction`（ADD COLUMN，不重建表——0019 级联事故教训）。
- 指令贯通三处注入点：单段分析、纠错重试、长文分段合并；上限 500 字符。
- **质量闸门指令感知**：有指令时栏目取舍由用户决定，空栏目不再判 Blocking（原先
  「至少 N 条关键观点」会与「只保留待办事项」直接冲突）；模型完全没产出仍触发纠错；
  引用逐字校验始终强制。
- 前端：分析面板「补充要求（可选）」输入框，进入记录时回显最近一次指令。

### A2 章节 + 金句

- `AnalysisDraft.chapters / highlights`（serde default，老分析 JSON 兼容）。
- 提示词与 Ollama JSON schema 同步扩展；长文合并按时间序去重章节、只保留输入中的逐字金句。
- 校验：章节缺引用或时间倒序整章丢弃（不整单失败）；金句 quote_text 必须逐字匹配所引片段，
  否则整条丢弃；两者都补 start_ms/end_ms 供点击跳播。
- 检索与导出：章节标题/摘要与金句文本进 `record_search`；金句落 `citations` 行；
  md/txt 导出增「章节」「金句」两节；分析视图可点击跳播。

### A3 防幻觉与不确定性措辞

- 提示词增「不确定性规则」：只有逐字稿确实存在听不清/缺失内容时才在摘要末尾说明缺口，
  **材料完整时不得杜撰缺口说明**（E2E 实测发现旧措辞会诱发模型凭空写「有 N 处内容不清晰」）。
- 「只保留/只输出 X」的**确定性栏目裁剪**（`apply_instruction_section_filter`）：7B 本地模型
  会被「保留一点也不影响」带偏，仅靠提示词无法保证；识别不出点名栏目时不裁剪（宁可少动）。
- 统一收口 `finalize_analysis_draft`：别名解析 → 指令裁剪 → 引用校验，分析/重新校验/E2E 三处共用。

### A4 质量评测矩阵与结构闸门

- `docs/analysis-quality.md`：两道门（自动结构闸门 + 人工五维矩阵 T1–T9）。
- `tests/analysis_quality_e2e_test.rs`（`ECHO_E2E=1` 手动门控）三场景：长文证据链、
  指令覆盖默认结构、材料不足不编造。2026-10-14 首跑（qwen2.5:7b）：**三场景全过**。

## 3. B 组：工程护栏

### B1 磁盘空间预检与低空间横幅

- `disk_space` 模块（statfs；向上找存在的祖先目录）。三处写前预检：导入拷贝前、
  预处理前（三引擎共用 `ensure_preprocess_space`）、模型下载前。
- 空间不足归 `AppError::Storage`：报错含需量/现量，且可直接判定「重试无用」（B3 复用）。
- 可用 < 2GiB 时工作区横幅提醒（每分钟刷新，只提醒不阻塞）。

### B2 存储可见性与无损清理

- `storage` 模块：分类占用报表（audio/raw/models/exports/db + 磁盘可用 + 可清理预览）、
  启动静默清理、设置「存储」分区（分类占用 + 一键清理 + 资料库路径）。
- 清理范围保守：只处理 raw/ 下 UUID 命名目录；记录已删除 → 整目录；记录存在但无活跃任务 →
  清理可再生产物；活跃任务与非 UUID 目录一律不动。
- **不做自动删除原件**：对方的原件只是云端缓存，我们的音轨是本地资产——删掉就永久失去回听
  与重新分析能力。用「可见 + 可控 + 低空间提醒」替代自动过期（条文写进 UI 说明）。

### B3 转写失败有限自动重试 + aac 修复

- 失败分类白名单：I/O 抖动、Ollama/第三方服务暂时不可用、预处理进程偶发失败才自动重试；
  上限 2 次、退避 60/180 秒；沿用同一 job（attempt_count 继续累加），失败期间 last_error
  带「N 秒后自动重试」。
- 用「逐字稿版本是否新增」区分失败阶段：转写成功后失败的是分析，不重跑转写（有测试锁住）。
- 三条入口全部接入（手动转写 / 增强重转写 / 收件箱自动导入）。
- 启动自动重排：应用退出中断的转写任务自动重跑（`attempt_count < 3`），不再只留「请手动重试」。
- 修复收件箱与导入白名单不一致的旧 bug：aac 加入支持格式（symphonia/ffmpeg/afconvert 均可解）。

### B4 发布产物审计

- `scripts/audit-bundle.sh`：sourcemap、测试/开发残留、本机路径串（文本严格 + 二进制 strings）、
  开发端点（文本产物；二进制内嵌 devUrl 属预期）、生产 csp 开发 ws 通道（配置源检查）、
  版本号一致性（含 Info.plist）、entitlements 摘要。
- 接入：`release-macos.sh` 在 **公证前**审计 .app（不通过直接中止，省一次无效公证）；
  CI 在 frontend build 后审计 `dist`。
- 配置硬化：开发 ws 通道从生产 `csp` 移入 `devCsp`。
- 路径泄漏修复（自证发现的真问题）：对已发布 0.7.1 包跑审计，主二进制有 595 处、
  mcp 二进制有 34 处 `/Users/<开发者>` 路径。两处来源分别修掉：
  ① 依赖与源码路径记录 → release 构建加 `--remap-path-prefix=$HOME=/build`；
  ② 我们自己的 `env!("CARGO_MANIFEST_DIR")` 开发回退（remap 管不到 env!）→
  迁移源码回退改为只在 debug 构建携带，release 走 `Resources/migrations`。
  修复后 mcp 二进制计数为 0。
- 审计脚本自身的坑：`strings | grep -q` 会因 SIGPIPE + `pipefail` 让二进制检查永远"通过"
  （假绿），改用 `grep -c` 取计数；修正后同一份 0.7.1 包立刻报出上述路径串。

## 4. 验证与验收

- 每包收尾 `cargo test + clippy -- -D warnings + npm run build` 全绿；全量 20 个测试目标通过。
- 真机走查清单（待用户执行）：
  1. 记录详情 → 分析面板填「补充要求：只保留待办事项，按负责人分组」→ 开始分析 →
     其他栏目为空、待办可点击跳播；重进记录输入框回显该指令。
  2. 一条 20 分钟以上录音分析 → 有「章节」可点击跳播、「金句」为逐字原话；导出 md 含两节。
  3. 设置 → 存储：占用分类正确、可清理预览与一键清理有效、原件体积不受清理影响。
  4. 低空间横幅：磁盘可用 < 2GiB 时工作区出现提醒（可用磁盘工具临时占满验证）。
  5. 失败重试：把模型路径指向不存在的文件 → 立即失败（不重试）；
     临时移除内置 ffmpeg 触发预处理失败 → 观察 60 秒后自动重试。
  6. 审计脚本：`bash app/scripts/audit-bundle.sh app/dist` 应输出「审计通过」。
- 版本：打包前升 `0.9.0`（三处版本号 + README 功能清单在发布时统一刷）。

## 5. 明确不做

采集侧（录音采集/快记热键/系统内录）、流式输出、标签系统、云 ASR、链接导入、
自动删除原件策略——留给后续排期；报告中的提示词复刻草案不搬文案，仅作 A4 评测基准。
