# v1.4 体验优化 Loop：断点状态文件

> 断了重连的锚点：本文件是唯一进度真相。每完成一个包立即更新此文件并 commit+push。
> 重连流程：`git pull` → 读本文件 → 找第一个非 done 的包 → 从它的「当前步骤」继续。

## 规则

- 每个包固定流程：方案（写入本文件）→ 失败测试 → 实现 → 全量测试（typecheck/test:ui/build/cargo test/diff --check）→ commit（信息前缀 `v1.4-包N:`）→ 更新本文件 → push
- 每轮 3 包做完后：night-reviewer 对抗审查该轮 diff → P0/P1 修复（追加 commit）→ push → 进入下一轮
- 测试里的假凭据一律用常量引用（`apiKey: "字面量"` 形态会被安全扫描拦截）
- 不重做视觉；不动隐私红线；不动已发布功能的既有语义（改语义必须有测试锁定新旧口径）
- 提交在 main 分支直接进行（用户已授权），每包一个 commit
